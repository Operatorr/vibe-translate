# Credits, BYOK, and a model registry as data

Model selection is **data first, with an env escape hatch**: a `models` table holds one default row per task (`translate`, `explain`, `dictation`, `embed`). Current defaults are `openai/gpt-6-luna` (translate), `xiaomi/mimo-v2.5-pro` (explain), `google/gemini-2.5-flash` (dictation), `openai/text-embedding-3-small` (embed, 1536 dims, called via OpenRouter with the platform key). The worker resolves the active model at request time, and operators can flip a registry default with a single SQL update — no deploy. **In addition, per-task env overrides** (`TRANSLATE_MODEL` / `EXPLAIN_MODEL` / `DICTATION_MODEL`, plus the matching `*_REASONING`: `none` to disable reasoning, `minimal|low|medium|high` for effort) take precedence over the registry default when set; a user's BYOK per-task model still wins over both. See [BACKEND.md](../BACKEND.md) → `openrouter.ts → resolveCallTarget`.

The same task uses the same model for all paying and free tiers. The differentiator between tiers is **credits**, not model strength. Free users get 10,000 one-time welcome credits ($0.10 of provider usage); Pro users get 500,000/month ($5); Linguist (`team`) users get 2,000,000/month ($20). Annual billing grants 12× the monthly credits at activation and renewal, with discounted subscription prices. Paid plans have no time-limited trial. Every Segment created and Explain generated debits the user's `credits_balance` based on OpenRouter’s reported USD cost, retaining sub-cent precision. One displayed Credit covers $0.00001 of provider usage, and balances/ledger/purchase snapshots are integer microdollars (10 units per Credit). Public API payloads expose displayed Credits. The legacy `credit_cost_multiplier` column is retained for compatibility but no longer sets charges. Missing cost reports fall back to the resolved model’s current input/output/request prices from the public OpenRouter catalog, cached for five minutes. An unpriced model or unavailable catalog rejects platform calls before a hold; BYOK and cache hits bypass that lookup. Corrective retries aggregate tokens and costs across both attempts. A `credit_ledger` table records every grant and every spend for audit and billing transparency.

**Spend uses an atomic reservation, not a read-then-write check.** Before a paid model call, `reserveCredits` places a hold equal to an `estimateCredits` value via a conditional `update users set credits_balance = credits_balance - estimate where ... and credits_balance >= estimate`. That row-locking UPDATE is the concurrency gate: simultaneous requests serialize, so a user near zero balance cannot fan out many in-flight paid calls past a single stale `balance > 0` read (which is what a plain pre-check allowed). After the call, `reconcileSpend` settles the hold to the real provider cost; `refundReservation` releases it if the call fails or produces nothing billable. The reservation writes a pending `credit_ledger` row immediately and reconcile/refund rewrites or deletes it, so `users.credits_balance = sum(credit_ledger.delta)` holds at every step.

**Bring-Your-Own-Key (BYOK)** is available to all tiers. A user can store their own OpenRouter API key (encrypted at rest via AES-GCM with `CREDENTIALS_ENCRYPTION_KEY`) and optionally pick their own translate/explain models. When BYOK is configured, the worker calls OpenRouter with the user's key and skips credit accounting — the user pays OpenRouter directly. BYOK does **not** apply to embeddings: translation memory consistency requires every Segment to be embedded with the same model, so the platform owns the embedding call regardless of BYOK status.

We keep model IDs out of `tier.ts` so the free → pro story stays about capacity, not quality. We originally rejected env-based model IDs entirely, but **reversed that**: per-task `*_MODEL` / `*_REASONING` env overrides are now supported on top of the registry, because pinning a specific model + reasoning effort without a SQL round-trip is valuable for local dev and quick operator changes. The registry remains the durable production default and rollback path; env simply wins when present. We rejected tier-tiered model selection because it makes the free → pro upgrade story about quality drift rather than capacity, which is harder to explain. We rejected allowing BYOK for embeddings because mixing embeddings from different providers in one `segments.source_embedding` column breaks cosine search (vectors aren't comparable across models or dimensions).

## Consequences

- The embed default is `openai/text-embedding-3-small` at 1536 dims; `segments.source_embedding` is `vector(1536)`, within pgvector's 2,000-dim HNSW index limit. A future embedding-model change requires re-embedding every row — embeddings remain derived data.
- Free tier loses the `segmentsPerMonth` cap in favor of a `credits` cap. Free receives a one-time signup grant; paid plans receive credits on billing renewal. There is no time-limited trial.
- The `users` table grows wider: `credits_balance`, `credits_refilled_at`, `openrouter_api_key_cipher`, `openrouter_api_key_last4`, `byok_translate_model_id`, `byok_explain_model_id`.
- Worker requires `CREDENTIALS_ENCRYPTION_KEY` in the binding set. Rotating it requires re-encrypting all stored BYOK keys; see [SECURITY.md](../SECURITY.md).
- The BYOK code path skips credit checks. Defensive: if `users.openrouter_api_key_cipher` is non-null, we trust the BYOK path. If decryption fails, fall back to the platform path (don't 500 the request).
- Per-task model/reasoning overrides live in the worker Bindings (`api/_lib/env.ts`): `TRANSLATE_MODEL`, `TRANSLATE_REASONING`, `EXPLAIN_MODEL`, `EXPLAIN_REASONING`, `DICTATION_MODEL`, `DICTATION_REASONING`. Per-task resolution order: BYOK model (translate/explain only) → env `*_MODEL` → registry default. Reasoning is sent to OpenRouter as `reasoning: { enabled: false }` for `none`, or `reasoning: { effort }` otherwise; a no-op (or the model's floor) on models that always reason.

## Cost-unit migration (0012)

Migration 0012 converts existing ledger, balances, top-up snapshots and stored Segment charges together. The signup grant becomes 10,000 Credits; recorded Luna spends are repriced from input/output token counts at $0.10/$0.50 per million tokens. Known USD costs take precedence in the ledger. Other historical charges retain their converted monetary value when actual cost is unavailable. Original ledger amounts are preserved in `metadata.legacyCredits`. Paid grants/top-ups retain their converted monetary value; the larger paid allowances apply at the next grant. Run with all old worker calls drained, then deploy the matching worker and SPA.

The public display scale is 10 microdollars per Credit (10× the initial 0012 display). Migration 0013 updates column descriptions only; USD budgets and integer accounting amounts remain unchanged. Existing balances, historical spends and purchased packs all display at the same new rate.
